## Architecture and implemented behavior

- Numeric lexing validates single separators between digits in decimal/hex/exponents and rejects identifier suffixes such as 12abc. likelihood requires a literal floating probability in [0,1], including during empty-input binding. Supplied unhex adjacency rules were reviewed and existing implementation retained.
- `lex/parser/ast`: handwritten scanner and Pratt parser. SQL expressions/queries and schema programs have serde support. Limits: parser/expression nesting 128, query nesting 60, JSON nesting/path 200, recursive CTE extraction 1,000,000, trigger recursion 100.
- `value/query/rowvalue`: NULL and dynamic storage classes; affinities, casts, collations, numeric overflow, row values, SELECT/VALUES, joins including RIGHT/FULL/NATURAL/USING, grouping/HAVING, compounds, ordering/limits, correlated subqueries and CTEs. Field.has_collation distinguishes an actual BINARY collation from no collation. Slot expressions bind expanded stars unambiguously.
- Recursive CTEs use an extraction queue with ORDER priority, LIMIT/OFFSET, compound seeds/recursive terms, forward dependencies and optional RECURSIVE. Bodies bind once even when LIMIT is zero. Ctes now wraps HashMap with a generation ID: clones retain the generation, insertion changes it, and new creates a fresh scope.
- `subquery`: shape-only binding records whether lookup resolves an outer Ctx. Query IDs are unique, cloned with ASTs, and skipped in serialization. Uncorrelated scalar/IN/EXISTS results cache by query ID, CTE generation and mode; caches clear at each execute request. Correlated results are reevaluated. View sources use fresh, empty CTE scopes and no caller row context; trigger OLD/NEW insertion creates new generations. BindingProbe stores context addresses only for comparison, never dereferences them.
- `query_capped` accepts a requested row count for scalar/EXISTS evaluation. LIMIT 0 binds metadata without projected-value evaluation. Simple filters/projections and unordered UNION ALL stop after enough rows while still binding later terms. DISTINCT/window/group counts are preserved. EXISTS skips unused projection/order values for simple queries, using a nonzero scoped query-depth marker. CASE NULL skips WHEN operands; row-value BETWEEN evaluates its LHS once.
- `cte`: complete query/expression/DML source dependency traversal with nested WITH shadowing and transitive forward references. Only reachable definitions are evaluated; unused CTEs can contain unbound tables/functions without affecting execution. Recursive CTE validation permits one top-level FROM reference (including parenthesized joins) and rejects hidden/subquery/seed/limit references and later nonrecursive terms. `schema_edit` still uses its older eager CTE binding path.
- `windowdef`: validates named-window chaining, including the distinction between OVER name and OVER(name). Window.chained is preserved by rendering. Windows support ROWS/RANGE/GROUPS, exclusions, filters, ranking/value/aggregate functions and grouped windows.
- `dml`: shared candidate selection for UPDATE/DELETE, UPDATE FROM and INSTEAD OF views; LIMIT/OFFSET and comma form, declared/explicit sort collations, negative/unlimited bounds, and membership selection independent of mutation order. LIMIT 0 binds expressions and source/view shapes without evaluating values. Trigger parser rejects limited UPDATE/DELETE, and ORDER BY requires LIMIT. Bounds are evaluated once. Rightmost duplicate SET assignments are evaluated only once per column, including partial literal tuples, rowid aliases and UPSERT. Partially needed row-subquery assignments still evaluate the complete subquery; CTE liveness still includes ignored assignments.
- `replace`: implicit REPLACE deletions execute FK actions and, iff recursive_triggers is enabled, DELETE triggers. Deleted conflict rows do not directly affect change counters; FK/trigger actions do. Conflicts are rechecked after deletion triggers. RAISE IGNORE skips the candidate; NOT NULL defaults recompute affinities/generated columns before remaining constraints. FK validation is deferred through trigger bodies to the outer statement, while RESTRICT remains immediate. FAIL exits validate FK/read-only/page-limit invariants and become ABORT on violations. View DML now also uses fresh CTE scope.
- `db`: DDL/DML, conflict algorithms, UPSERT, RETURNING, rowids/AUTOINCREMENT/sqlite_sequence, strict/without-rowid/generated columns, checks, foreign keys/actions/deferred constraints, row and INSTEAD OF triggers, changes()/total_changes()/last_insert_rowid(), transactions/savepoints.
- Foreign validation tolerates violations that existed at the transaction/statement baseline. Row.birth is an internal fresh identity (not stored in SQLite records), preventing deleted/reinserted rows from inheriting historical exemptions. Parent matching uses declared collations, accepts reordered unique target columns and preserves STRICT ANY affinity. Cascades enforce child constraints and trigger hooks.
- `schema/schema_edit/render`: temp/main/attached name resolution, attachment-order search, bound persistent views/triggers, ALTER rename/drop dependency checks and SQL rendering. Canonical internal table accesses use table_key, preventing temp shadowing from redirecting already-resolved DML, FKs or storage. INSTEAD OF view triggers participate in column renames. Literal string values are preserved during expression-equivalence matching.
- `introspect`: table/view/index/foreign-key PRAGMAs and table functions with a final schema argument. Qualified reports use live transaction state. WITHOUT ROWID primary and auxiliary index columns are reported, including synthetic PK index names. Temp schema persists after its last object is dropped.
- `storage`: native SQLite 3 headers, varints/records, table/index B-trees, overflow and freelists. UTF8/UTF16le/UTF16be reading and writing preserve encoding; new encoding selection, attached encoding checks, connection CAST and octet_length are implemented. Table.primary_key preserves order/collation/DESC and deduplicates only identical column/collation terms. Key suffixes share that definition.
- Structural checks cover page ownership, headers, bounds, freeblocks, cell overlaps and freelists. Integrity checks also verify stored row/index ordering, index record widths and index/table correspondence; quick_check skips uniqueness/correspondence. Partial table checks work. Shared index_layout/index_records code drives both writing and checking.
- `analyze`: real ANALYZE (database/table/index/synthetic WITHOUT ROWID PK/all schemas), persistent sqlite_stat1 with collation-aware prefix statistics and partial/expression index support. Statistics are snapshots; ordinary DML does not refresh them. Internal creation/import, writable stat rows, prohibited ALTER, transactional DROP/rename maintenance and native reopen are tested. Schema-root catalog mappings preserve statistics across renames and remove dropped-object entries.
- `analyze` also implements analysis_limit (31-bit connection setting, bounded prefix sampling, optional second sample after a constant leading-key run) and optimize masks/scopes/debug mode, missing/stale index detection, query history and temporary limits. Index records are still fully materialized and sorted before bounded statistics scanning. optimize upgrades existing read locks without refreshing the statement snapshot and rejects stale WAL snapshots; diagnostics/no-op calls work with query_only. Connection.observed_tables tracks table queries for optimize.
- `reindex`: index/table/collation/EXPRESSIONS/all-schema rebuilds, uniqueness validation and transactional repair. State.rebuilds is a per-schema generation marker included in snapshots, not SQLite pages. Import/export, refresh and VACUUM preserve its schema scope. A complete-image commit regenerates all indexes in a changed file, even when one index was selected.
- `persistence/locking/journal`: commits compare persistent schemas excluding regenerated SQL text and write only changed files. Connection.main_disk_state holds the committed baseline; own_commit_version distinguishes local commits from data_version changes by other connections. database_image uses committed bytes when unchanged, otherwise current encoded state. Actual page/freelist counts include uncommitted changes. Read-only future-write-format files permit temp/other-schema work and VACUUM INTO while rejecting mutations to the read-only schema.
- Commits use fsync plus atomic rename, advisory flock sidecars and durable multi-file backup manifests. Pending manifests restore all originals; committed manifests retain all new images. busy_timeout retries writer/read/commit locks. Deferred/immediate/exclusive transactions and own-process WAL-style snapshots pass multiprocess tests.
- `pagelimit`: per-main/attached/temp max_page_count, clamped to current size and the documented 4294967294 maximum. Custom limits are checked after each changed statement and in encoding; FULL errors restore that statement while keeping prior transaction work. Page roots allocate within each schema, and autoindex name numbers no longer consume unused root slots.
- `vacuum/settings`: root compaction, schema-selected VACUUM, scalar INTO expressions, pending page sizes outside WAL mode, temp preservation. Journal mode setters distinguish explicit schema from unqualified all-schema scope; memory accepts MEMORY/OFF; non-WAL mode switches avoid rewriting files. temp_store changes drop all temp objects outside transactions.
- `format`: SQL printf/format engine with dynamic widths/precision, integer signs/bases/prefixes/grouping, Unicode-vs-byte string widths, quote/identifier/control escaping, f/e/g notation, 16/26 significant digits and output bounds. SQL-specific %p is %X and %n consumes no argument. Supplied docs specify NULL %q as empty and %#g removing trailing zeros; implementation follows those descriptions. UTF8 precision splitting a character produces replacement text, consistent with our text representation limit.
- `func/date/jsonfunc`: broad scalar/aggregate functions, UTC civil dates/modifiers/strftime/timediff with statement-stable now, JSON/JSON5 ordered objects and duplicate keys, paths/mutation, json_each/tree, percentiles/median, Unicode escapes, iterative LIKE/GLOB with long-input checks.

## Remaining work / candidates

1. Native WAL and rollback-journal codecs and native-library locking interoperability remain absent. WAL mode currently uses complete atomic images and snapshot semantics. Multi-file recovery is our own documented manifest scheme. Review rare I/O failures during commit-marker writes/cleanup.
2. prepare_access still acquires locks and snapshots across all attached schemas for each access, broader than necessary. Per-schema lazy snapshots and read/write sets would improve independent-file concurrency. Literal dots remain conflated with qualification in flat catalog keys.
3. Query execution still materializes FROM inputs; limits do not avoid all unnecessary source evaluations. Ordered/compound DISTINCT subqueries may compute unused projected values. Review caching with complex nested view/CTE scope changes. Review complex dependency graphs and schema edits of unused CTE bodies.
4. ALTER has remaining scope/alias edges, including complex nested CTEs, compound labels and UPDATE FROM/UPSERT expressions in triggers. Rewritten expression labels can differ before/reopen. USING rename post-validation should prevent invalid one-sided joins.
5. Planner/EXPLAIN remain placeholders; indexes are not used to accelerate queries. Many paths are quadratic except guarded plain-rowid bulk INSERT. Virtual-table extensions and JSONB are unavailable. temp_store FILE still uses memory. auto_vacuum and some other pragmas are unimplemented.
6. Some floating-point/date/math/aggregate precision and error-timing details remain. UTF16 storage/casts work, but detailed collation ordering and all BLOB-to-text function conversions across encodings need review. Scalar-subquery affinity outside row-value contexts deserves further documentation review.
7. Storage checks do not yet validate every interior separator or pointer-map entry. Full-image encoding naturally compacts more than a pager would and rebuilding one index repairs other indexes in that file. Structural corruption is often rejected during open, earlier than a demand-loaded engine would detect it.

Literal empty IN/NOT IN now skips LHS evaluation after normal binding. Runtime-empty subqueries retain their existing evaluation path. Latest candidate: validate table B-tree interior separator keys and additional page-layout invariants. No storage edits for this candidate yet. Continue useful progress from this integrated state.
