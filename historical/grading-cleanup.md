## Minimal explicit adapter

evaluate.py imports the byte-unchanged evaluator/evaluate_snapshot.py using its actual file path, retaining its ROOT. It replaces only JsonProcess.close and docker_cleanup. JsonProcess initialization, protocol reader, serialization, request handling, Normalizer, score_file, corpus selection, query/statement scoring, build command, image, per-container isolation/resource ceilings, request deadline (10 seconds), per-file deadline (300 seconds), and build deadline remain inherited and unchanged.

On killpg EPERM or ESRCH, cleanup polls the original unreaped Popen child. If it has exited, cleanup reaps it. Otherwise it calls Popen.kill on that owned child only, then confirms exit within five seconds. Other signal errors or inability to confirm exit stop the evaluation. No elevated permission, arbitrary process-group targeting, or implementation restart is used. The frozen evaluator subsequently removes its uniquely named container, and its outer finally also attempts removal after exceptions. The adapter confirms removal with an exact-name Docker inventory query; it allows a bounded wait for removal already in progress and rejects query errors or lingering containers. Only the evaluator's existing generated engine/build name format is accepted.

Cleanup timeouts become CleanupError (an infrastructure error), not subprocess.TimeoutExpired: the frozen evaluator catches the latter as a build deadline and marks a valid zero. Thus unconfirmed cleanup cannot silently become a build-failure zero. A cleanup error may leave an incomplete or absent summary, which the dispatcher rejects and preserves. The adapter annotates its own summaries with evaluator_revision=cleanup-recovery-001. It never rewrites an existing output directory. Production has no fault-injection option; injection is confined to diagnostic/test harnesses.
